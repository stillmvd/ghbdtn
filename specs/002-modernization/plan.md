# Implementation Plan: Модернизация по итогам разбора аналогов

**Branch**: `main` | **Date**: 2026-10-16 | **Spec**: [spec.md](spec.md)
**Input**: `specs/002-modernization/spec.md`, исследование `.planning/RESEARCH-ANALOGS.md`

## Summary

Догнать Punto/Caramba по скорости и устойчивости к быстрому набору (единая пачка ввода, профиль и ускорение движка,
ранняя правка по началу слова), снять 375 МБ постоянных WebView2, добавить стратегии по программам (включая DLL смены
раскладки изнутри потока), надёжность хука после сна и мелкие правила P2. Сохранить лидерство по точности: корпус и
стенд не ухудшаются ни по одной метрике.

## Technical Context

**Language/Version**: Rust (workspace `src-tauri`, крейт `ghbdtn-core`), TypeScript + React 19 (UI)
**Primary Dependencies**: `windows` (windows-rs), `fst`, `crossbeam-channel`, `arc-swap`, Tauri 2
**Storage**: конфиг TOML, словари внутри exe
**Testing**: `cargo test` (юнит + корпус `--test corpus`, `rule_stats`), стенд `core/examples/rivals.rs`,
`core/examples/selftest.rs`, `pnpm check`
**Target Platform**: Windows 11 x64
**Performance Goals**: движок ≤ 15 мс ср от разделителя до конца `SendInput`; на экране p50 ≤ 40 мс; очередь 12/12
**Constraints**: колбэк хука без работы (конституция II); приватность (I); ложных не больше (III); память ≤ 100 МБ
**Scale/Scope**: ~11 фаз, одна DLL-крейт, правки ядра, UI настроек, оверлей

## Constitution Check

| Принцип | Как соблюдаем |
|---|---|
| I. Приватность | стенд и профиль пишут только времена и счётчики; DLL не видит текст; буфер обмена восстанавливается |
| II. Мгновенный хук | колбэк не меняется по сути; задержка клавиш — флаг; профиль — атомики `Instant` уже в `RawKey.at` |
| III. Не ломать ввод | ранняя правка — двойное подтверждение по префиксу (1.1.0), пороги по корпусу, «осторожно» не хуже текущего |
| IV. Отменяемость | ранняя правка и правила P2 пишутся в `undo`-книгу; двойной Shift = отмена |
| V. Исключения | стратегии по программам не обходят проверки, DLL — только для программ из списка |

Отступлений нет.

## Подход по фазам

1. **Замеры**: стенд в репо; разбивка времени движка по шагам (очередь → evaluate → decide → SendInput → смена
   раскладки) в счётчиках `hook::*`, вывод в `rivals`/`selftest`; тестовая метка `TEST_MARK` в установленной сборке
   при `GHBDTN_ACCEPT_TEST_INPUT=1`; базовая линия в `bench/`.
2. **Скорость**: убрать найденные по профилю узкие места (кандидаты: Win32-запросы в `evaluate` на каждый разделитель,
   `has_ru_en`, `far_fix`, разбиение `SendInput`, ожидание раскладки до 50 мс в пути исправления).
3. **Очередь**: исправление + задержанные клавиши одной пачкой `SendInput` в исходном порядке; задержка держится до
   конца смены раскладки; тест порядка на `Worker::release`.
4. **Ранняя правка**: таблица начал слов (FST/префиксный поиск по словарям и словоформам), правило «начало невозможно
   здесь и уверенно возможно там», порог длины ≥ 3–4; новые тесты корпуса «ранние ложные»; запись в книгу отмены.
5. **Промахи и сигналы**: «ye jr» → «ну ок», «teh» → «the»; не трогать слово после ручной смены раскладки; сверка
   клавиш сброса; переустановка хука по `WM_WTSSESSION_CHANGE` и выходу из сна.
6. **Стратегии ядра**: `ProgramProfile` в конфиге; вставка Unicode / буфер (CF_UNICODETEXT с восстановлением) / VK через
   `VkKeyScanExW`; смена раскладки сообщением / системным сочетанием (из реестра `Keyboard Layout\Toggle`); опрос
   3 мс до 250 мс и повторы; таблица по умолчанию (мессенджеры → буфер; VS, Office, Zoom, Skype → сочетание; Word +
   задержка).
7. **DLL**: крейт `layoutdll` (x64 cdylib): поток-специфичный `WH_GETMESSAGE` на поток окна, зарегистрированное
   сообщение → `ActivateKeyboardLayout` внутри потока; снимается после; только для программ со стратегией «изнутри».
   Сборка и упаковка в установщик.
8. **Правила P2 (ядро)**: Caps Lock и две заглавные; ёфикатор (список слов с «ё» из OpenCorpora); двойной Shift;
   уровень чувствительности как множитель порогов; таблицы раскладок из `kbdXX.dll` с откатом на встроенную карту.
9. **Стенд настроек** (развилка с пользователем): таблица программ, уровень, ёфикатор, двойной Shift, Caps — один
   стенд-артефакт, затем UI.
10. **Память UI**: настройки и меню трея — создавать/уничтожать; подсказка у курсора — нативное слоёное окно с тем же
    видом; замер ≤ 100 МБ.
11. **Приёмка и релиз**: стенд по установленной сборке, память, ручные проверки (сон, программы), `pnpm release` с
    согласия.
